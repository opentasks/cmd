# Configuration System (config.toml)

## Design Decision

Configuration is optional and partial. Projects work without config using sensible defaults. Config can be extended at any level (built-in → user → project).

## config.toml Structure

All sections are optional. If missing, built-in defaults apply.

```toml
[project]
name = "My Project"
description = "A brief description"
owner = "team-name"

[workflow]
# State machine: which statuses exist and valid transitions
statuses = ["todo", "in-progress", "reviewing", "done", "archived"]
initial = "todo"

[[workflow.transitions]]
from = "todo"
to = ["in-progress", "archived"]

[[workflow.transitions]]
from = "in-progress"
to = ["reviewing", "todo", "archived"]

[[workflow.transitions]]
from = "reviewing"
to = ["done", "in-progress", "archived"]

[[workflow.transitions]]
from = "done"
to = ["archived"]

[templates]
# Optional paths to template files
# If not specified, falls back: config → project → user → built-in
epic = "./templates/epic.md"
plan = "./templates/plan.md"
research = "./templates/research.md"
story = "./templates/story.md"
decision = "./templates/decision.md"
task = "./templates/task.md"

[storage]
# Which storage backend to use (default: "markdown-fs")
backend = "markdown-fs"
# Backend-specific configuration
path = "/custom/path"
```

## Built-in Defaults

**Status Workflow**:
```
todo → in-progress → reviewing → done → archived
```

**Templates**: Provided in `${XDG_DATA_HOME}/opentasks/templates/`

**Storage**: Markdown filesystem at project root

## Template Resolution Hierarchy

When creating a task of type "story":

1. Check `config.toml#templates.story`
2. Check `{project-root}/templates/story.md`
3. Check `${XDG_DATA_HOME}/opentasks/templates/story.md`
4. Fall back to built-in template

This allows customization at any level without requiring full config.

## Implementation Notes

- config.toml loaded at project initialization
- Missing fields use defaults (no required fields)
- Workflow transitions validated when loading config
- Storage backend config passed directly to storage implementation
- Templates resolved at task creation time (lazy loading)
