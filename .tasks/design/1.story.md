# Task Data Model and Relationships

## Design Decision

Tasks are represented with a core struct containing metadata and a flexible relationships slice.

## Task Structure

```go
type Relationship struct {
    Type   string // "parent", "blocks", "relates-to"
    TaskID int    // e.g., 42, 5 (global sequential ID)
}

type Task struct {
    ID            int           // Global sequential ID (e.g., 42)
    Title         string
    Type          string        // epic, plan, research, story, decision, task
    Status        string
    Tags          []string
    Description   string        // markdown body
    Relationships []Relationship
    CreatedAt     time.Time
    UpdatedAt     time.Time
}
```

## Rationale

- **Single relationships source of truth**: Relationships slice eliminates redundancy
- **Flexible relationship types**: Easy to add new types (parent, blocks, relates-to) without schema changes
- **Clean frontmatter mapping**: Serializes naturally to YAML
- **Type system**: All task types (epic, plan, research, story, decision, task) supported equally

## Frontmatter Example

```yaml
id: 42
title: Implement task linking
type: story
status: in-progress
tags: [feature, core]
relationships:
  - type: parent
    taskID: 5
  - type: blocks
    taskID: 10
  - type: relates-to
    taskID: 3
createdAt: 2025-11-02T10:00:00Z
updatedAt: 2025-11-02T10:30:00Z
```

## Implementation Notes

- Description stored in markdown body below frontmatter
- All timestamps in UTC RFC3339 format
- IDs validated at load time (must be positive integers)
- Relationships validated: target task IDs must exist
- See research docs for complete field specifications and file organization
