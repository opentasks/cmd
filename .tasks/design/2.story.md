# Semantic ID System with Collision Detection

## Design Decision

Task IDs are semantic, sequential identifiers with per-type counters and collision detection via letter suffixes.

## ID Format

- **Prefix**: Single letter per task type (e, p, r, s, d, t)
- **Sequence**: Sequential counter per type (s-1, s-2, s-3...)
- **Collision suffix**: Letters appended on collision (s-42a, s-42b)

## Type Mapping

| Type      | Prefix |
|-----------|--------|
| epic      | e      |
| plan      | p      |
| research  | r      |
| story     | s      |
| decision  | d      |
| task      | t      |

## ID Generation Strategy

1. **Count existing files**: Glob for `*.{type}.md` files in project
2. **Determine sequence number**: count + 1 = next ID
3. **Check for collision**: If `s-42` exists and we're creating `s-42`, append suffix
4. **Return ID**: e.g., `s-43` or `s-42a`

## File Naming Convention

Tasks saved as `{sequence}.{type}.md`:
- `1.epic.md` (e-1)
- `42.story.md` (s-42)
- `8.plan.md` (p-8)
- `42a.story.md` (s-42a, collision case)

## Implementation Notes

- ID generation is **storage backend responsibility** (part of BaseStorage interface)
- Filesystem is source of truth for sequence numbers
- No persistent counter state needed
- Collision handling is rare safety valve, not primary mechanism
- File extension indicates type, allowing quick globbing
